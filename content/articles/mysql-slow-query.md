## 先定位慢 SQL

打开慢查询日志，或者用 EXPLAIN 分析 SQL 的执行计划，重点关注 type 列（是否全表扫描 ALL）、key 列（是否走了索引）、rows 列（扫描行数）。type 为 ALL 说明没走索引，是首要优化对象。

## 索引与 SQL 写法

给 WHERE、ORDER BY、JOIN 的关联字段建索引；避免在索引列上做函数运算（会失效）；避免 select *，只查需要的列；避免隐式类型转换导致索引失效。这些是成本最低、收益最高的优化。

## 架构层面优化

数据量大了之后，单靠索引不够：热点数据用 Redis 缓存，减轻数据库读压力；读多写少可以主从分离；单表太大考虑分库分表。本项目的检索压力已经外置到向量库，MySQL 只承担业务数据存储，正是一种架构层面的减负。
