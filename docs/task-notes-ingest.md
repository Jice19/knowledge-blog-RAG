# 开发任务：个人笔记（17 万字大文档）接入知识库

> 关联：`task-chunk-overflow.md`（切片策略）、`implementation.md`（入库链路）
> 简历卖点：「结构化笔记知识库：多级标题切片 + 完整标题路径溯源，支持超大文档按章节自动拆分入库」
> 优先级：高（用户真实数据接入）

---

## 1. 背景与目标

**现状**：知识库里只有 26 篇精修文章 + 306 篇 mock 文章。用户有一份 **17 万字个人笔记**（单 Markdown 文件），涵盖前端、后端、Agent、面试题、手写题，**有明确标题命名但内容自由书写**。

**目标**：把这份超大文档接入知识库并**确保检索与溯源效果**——切片语义完整、能溯源到具体小节、检索召回准确。

---

## 2. 三层拆分设计

```
17 万字单文档
  │ ① 按 # 一级标题拆
  ▼
N 篇「文章」（每篇一个主题，如《Redis 笔记》《手写题汇总》）
  │ ② 按 ## / ### 标题切
  ▼
M 个「切片」（带完整标题路径：Redis > 缓存 > 穿透）
  │ ③ 超长按句再切 + overlap（复用现有逻辑）
  ▼
Qdrant point
```

**为什么必须拆文章**：单文档当一篇文章，溯源只能显示"《我的笔记》- 某小节"，无区分度；拆成多篇后溯源为"《Redis 笔记》- 缓存穿透"，检索也更精准。

---

## 3. 需求（按点）

1. **拆文章**：按 `#` 一级标题把大文档拆成多篇文章，每篇带标题 / 摘要 / 分类
2. **多级标题切片**：`ChunkService` 支持 `# / ## / ###`，切片 heading 存**完整路径**（`一级 > 二级 > 三级`）而非单级标题
3. **跳过代码块**：手写题里代码注释的 `#` 不再被误判成标题（扫描标题时跳过 ``` 代码块）
4. **分类自动推断**：拆分时按标题关键词推断分类（前端/后端/Agent/面试题/手写题/个人笔记），导入脚本动态建分类
5. **参数调优**：`chunk-max-chars` 从 1000 下调到 600（贴近 mxbai 512 token 上限，中文更安全）

---

## 4. 实现方案（按点）

### 4.1 ChunkService 改造（多级标题 + 完整路径 + 跳代码块）

- 用正则 `^(#{1,3})\s+(.+)$` 识别标题，维护 `h1/h2/h3` 三级上下文
- 遇到标题：先按**旧路径**落当前切片，再更新标题上下文，新切片从标题行开始
- 切片 `headingPath = h1 > h2 > h3`（空级跳过），沿用现有 `splitOverflow` 超长兜底
- 用 `inFence` 标记跳过 ``` 代码块内的标题检测（代码内容仍照常进切片）
- 兼容现状：无 `#` 标题的旧文章，行为不变（`##` 仍是顶层）

### 4.2 split_notes.py（按 # 拆文章）

- 读取源 md，按 `# ` 行切分成多个 section（无 `#` 则退化为按 `## ` 切）
- 每个 section → 一个带 frontmatter 的 md：`title`（一级标题文本）/ `summary`（首段前 120 字）/ `category`（标题关键词推断）
- 输出到 `content/articles/`，文件名 `notes-序号-标题slug.md`

### 4.3 import_articles.py（动态建分类）

- 先解析全部文章的 frontmatter，收集用到的分类
- 查重后对缺失分类动态创建（slug 优先查表，否则自动生成），不再因"未知分类"跳过文章

### 4.4 参数调优

`application.yml`：`chunk-max-chars: 600`（`chunk-overlap-chars: 100` 不变）

---

## 7. 风险与备注

1. **重建影响全库**：ChunkService 改动后需删集合全量重新入库（含 26 篇精修文章 + 笔记 + mock），耗时取决于 Ollama
2. **mock 文章仍在库**：会与真实内容抢召回，建议后续下线（单独决定）
3. **标题命名决定效果**：拆分与溯源质量依赖笔记的标题清晰度；标题含糊的小节溯源会弱
4. **分类推断是启发式**：按标题关键词匹配，可能有误判；拆完后建议人工扫一眼分类，改 frontmatter 即可修正
